# 2026-08-08 工作日志

## MDG-016 页眉页脚模块深度审计

完成了对 Docsy 项目页眉页脚模块的全面代码审计，覆盖 4 个 Rust 后端文件 + 6 个前端文件（约 9400 行代码）。

### 核心发现

**问题 A（删除失败）根因**：检测用 pdftotext（poppler，带 ToUnicode CMap），删除用 lopdf（仅处理 UTF-16BE/UTF-8，无 CMap 查找）。CID 字体（中文）检测到真实文本，但删除时 lopdf 解码出 GID 乱码，文本匹配必然失败。bbox 兜底匹配也因坐标系方向相反（pdftotext 原点左上 y 向下，PDF 原生原点左下 y 向上）而不可靠。zone check 作为 gate 进一步阻止了 bbox 匹配。

**问题 B 根因**：`buildHeaderText`（旧 API）在 `headerEdited=true` 时无条件用 `file.header`（文件名），忽略当前 headerMode。渲染路径用 `buildHeaderTextForGroup`（新 API）直接用 `group.text`，导致不一致。

**问题 C 根因**：UI「按证据列表名称」映射到 `per_file` 模式，但 `per_file` 返回 `file.header`（默认文件名），而非证据序号。

**问题 D**：`expandSplitNameTokens` 中 `[#]`/`[序号]` 始终从 `index+1` 开始，无起点/步长参数。

### 修复建议优先级
- P0: bbox 匹配独立于 zone check + 坐标系统一（2-3天）
- P0: buildHeaderText 的 headerEdited 仅在 per_file 模式生效（0.5天）
- P1: per_file 语义修正 + 序列起点/步长支持
- P1: Form XObject 坐标变换
- P2: dingbat 页码 Unicode 修正（0x2775→0x2776+value-1）、文本拼接匹配、新旧API统一

## 交叉审计更正

与 Claude 审计交叉验证后，修正了 GLM 审计中的两处错误：

1. **dingbat Unicode — 非 bug**：`0x2775 + value` 是正确的。value=1 → 0x2776=❶。原报告误将基数 0x2775 当作目标字符。已有测试验证。无需修复。

2. **normalize_for_match 不一致 — 非根因**：两个函数在不同路径上工作（pdftotext 检测路径不用 normalize_for_content_match），不是检测-删除不匹配的原因。但统一仍有可维护性价值，降级为 P2。
