## 1. 给实施者的任务

在保持现有用户行为和工作区修改的前提下，为 Docsy 建立可验证的 PdfCraft 原生页面组织候选后端。先交付能编译、能选择、能与旧后端对照的实现，再按验收结果逐项扩大能力。

第一轮必须完成阶段 0、1、2，以及阶段 5 中与这轮变更有关的验证。阶段 3、4 在第一轮结果可复核后继续；不要把未来阶段的说明当成已经完成。

本轮不要求把软件重写为 Acrobat，不替换 Vue/Tauri，不更改 Office 转换引擎，也不把 AI/OCR 解析结果接到确定性的 PDF 修改链中。

## 2. 实施前检查

1. 阅读相关现有 docs，记录 HEAD、工作区 diff、版本和当前检查结果。
2. 研究时工作区已有 Word→PDF、前端导入及文件发布修复，且会继续变化；保留并按当前源码重新确认。
3. 对照研究文档固定提交。升级上游时单独记录新提交、动机、接口/行为变化和重跑结果。
4. 依赖范围保持最小。优先 cos/content/organize，禁止为了一个合并接口引入完整 engine/UI/OCR/JS/签名栈。
5. 核对 Rust MSRV、平台目标、Cargo patch 传播和文件级许可证。复制源文件时记录来源提交及改动，保留相关许可/NOTICE；不复制品牌、示例资产和不需要的字体。

## 3. 阶段 0：建立基线与保留政策

### 工作

- 将当前 qpdf 合并/提取输出收集为对照，不将它当作所有结构的完美标准。
- 区分两种语义：
  - **现有打印合并**：保持现有注释/签章外观压平、页序、双面补白和输出命名。
  - **结构保留合并**：保留可支持的交互字段、书签和附件；本阶段只在内部试验，不静默改变现有入口。
- 为每项操作列出保留/变换/拒绝/警告政策，至少包含 Info、自定义恢复数据、XMP、书签、跳转、附件、表单、标签结构、签名和加密。
- 明确“保留签章可见图像”与“保留证书签名有效性”的区别。

### 验收

- [ ] 工作区原修改完整保留。
- [ ] 对照样例包括结构合并与打印合并，命令和配置清楚。
- [ ] 确定不能处理时的行为；不能静默丢结构后返回成功。

## 4. 阶段 1：隔离适配层

建议新增 src-tauri/src/pdf/backend/，具体名称可按仓库规范调整：

| 文件 | 职责 |
| --- | --- |
| mod.rs | 能力、请求、结果和分派；不放厂商特定对象类型 |
| qpdf_backend.rs | 包装当前路径；避免因抽象顺手重写已验证逻辑 |
| pdfcraft_backend.rs | 固定依赖、cos 对象与组织 API；只返回 Docsy 自己的结果类型 |
| policy.rs | 输出政策、能力预检、签名/恢复数据/文档结构约束 |

不要先设计覆盖所有 PDF 操作的大 trait。第一轮只抽取页面读取、合并、提取需要的契约：

- 请求包含原始文件、页段、预期输出政策、补白规则、取消上下文。
- 结果包含实际输出路径、使用的后端、页数、警告、保留/变换项和回退原因。
- 能力通过具体操作及政策声明，不能只有 supports_pdf = true。
- 外部 Tauri 命令参数和原有返回形状优先保持兼容；扩展字段不能破坏前端。

后端选择先使用开发配置或测试注入，不在普通用户界面暴露实验性技术选项。默认依旧旧后端。

### 回退契约

- 只对预检认定的不支持格式/能力或已知兼容限制回退；不能以 catch-all 掩盖实现错误。
- 用户取消、权限/磁盘错误、输出发布失败不能触发另一个引擎重做。
- 回退前清理候选临时输出；输入和已有目标不受影响。
- 取消应传到正在执行的引擎。仅在调用前后检查 token，不代表能中止长时间解析。
- 候选引擎若不能可靠中断/限制内存，可先运行在独立 worker 进程，不强行嵌入主进程。
- 记录回退原因和后端，但日志继续遵守现有文件名/路径脱敏规则。

### 验收

- [ ] 开关关闭时当前行为与调用保持一致。
- [ ] 新依赖没有拉入 egui、boa、OCR 模型或整套应用运行时。
- [ ] 错误类型可区分取消、不支持、解析失败和 IO 失败。
- [ ] 失败/取消后不留下有效命名的半成品，原文件哈希不变。

## 5. 阶段 2：页面组织候选后端

### 2A：先实现结构模式的内部对照

使用 PdfCraft 固定提交的 cos::Document、organize::Combiner、extract_pages、write_full；以逐输入 Combiner::add 为起点，避免一次持有全部源文档。

页段对外仍为 1-based；边界处统一转换，不能在业务中散落 0/1-based 换算。

复用 Docsy 当前页面几何模型。不得因候选能读取 MediaBox 就忽略 CropBox、非零原点、继承、Rotate、UserUnit。双面补白复制最后一页的视觉尺寸约定，并保持现有末份奇数页补白行为。

### 2B：补齐文档级政策

已知不能直接照搬的行为：

- 提取接口未自动保留全部 Info、源书签和附件。
- 合并支持书签嵌套和附件，不代表结构树及自定义应用数据全部保留。
- 导入会改变对象编号。Info 中旧版、依赖对象编号的恢复备份不能盲拷贝。
- 同名字段的重命名必须与结果中的字段值、Widget /Parent /Kids、资源一致，不能只检查页面可见文字。
- 页被提取/重排后，源书签和命名目的地必须重映射，或按已声明政策拒绝/告警。

对 DocsyAntiCopyBackup：

1. 复用现有备份版本识别及拒绝规则。
2. 新版备份若按字体身份可恢复，需验证处理前后恢复文字、CMap 和相关字体标记。
3. 不满足条件时回退/拒绝，不能去掉备份后返回成功。
4. 使用现有 freeze 回归作为必过门槛，不因新后端更方便而修改预期绕过保护。

### 2C：打印模式兼容

只有结构模式通过后再接打印入口。

- PdfCraft organize 单独调用没有与 Docsy 当前压平流程等价的默认行为。
- 必须确认注释外观、共享 AP、缺 AP、隐藏标记、旋转页和表单外观的处理。
- 如果仍需要旧后端执行压平，结果中明确记录分阶段后端；不得宣称已移除 qpdf。
- 不因需要压平而把整页转成图片。

### 验收

- [ ] 三份以上混合页面尺寸/旋转/页序测试正确，补白规则正确。
- [ ] 合并、提取、倒序/非连续页段均经独立读回和结构检查。
- [ ] 附件、书签、表单、跳转的结果符合明确政策。
- [ ] Docsy 恢复链、字体子集、签章可见外观的回归通过。
- [ ] 候选默认路由仍关闭；结果可被 Codex 独立复现。

## 6. 阶段 3：可更新的 Docsy 标记

借鉴 PdfCraft edit 的独立流和 Artifact 分类，不直接照搬 WinAnsi 绘制。

- 保留当前 overlay_font 的中文子集、Unicode 映射与字体选择。
- 定义 Docsy 自己的版本化标记、类型和批次 ID，记录在内容流字典及必要的 marked-content 属性中。
- 更新/删除只定位自己的标记；普通正文、第三方页眉和历史 PDF 元素仍走现有检测/核对流程。
- 标记和绘制共用页面几何；明确 base 页 Rotate 与 overlay 补偿由哪一层负责。
- 对共享流采用 copy-on-write 或按页面拆出独立流，避免删除一页标记影响其他页。
- 明确最小范围修改、图形状态隔离及缺字体失败行为。

### 验收

- [ ] 新增→更新→移除后，原页面内容和其余标记保持一致。
- [ ] 中文、旋转四方向、CropBox、非零原点、混合尺寸通过。
- [ ] 历史无标记文件仍可按原流程处理。
- [ ] 不以黑色/白色遮盖充当物理删除。

## 7. 阶段 4：分开做优化与提取/预览 PoC

### 图片优化

先对照现有 compress.rs，避免重复有效 DPI 分析。只引入明确新增收益：

- 多条图像碎片合并；
- 多层 Form/共享图片用途测量的补强；
- 进度、取消和空间报告。

禁止将 PdfCraft Mobile/Standard 参数直接变成 Docsy 默认值。保留无损结构优化与有损图片压缩的入口区别。不得自动运行 sanitize、删除用户数据或降低文字可读性。

### PDF Oxide

单独适配文字、坐标和 Markdown，不接到 merge 输出路径中。

按相同页段与配置比较中文/竖排/双栏、ToUnicode 缺失、旋转、表格、脚注和扫描页。保留原页号、无文本页提示及稳定位置来源。模型/OCR 如未启用，不将空提取包装为成功识别。

### Hayro / craft-pdf

单独评估缩略图/预览，保持 PDF.js 和 Poppler 可用。必须使用一致几何、背景、DPI 与字体环境对照；裁剪、取消、深缩放和大图上限都需验证。不得将预览成功视作可安全写回。

## 8. 阶段 5：验收矩阵

以下都是待完成条目。研究中的小样本结果不能替代这一矩阵。

| ID | 样例/情形 | 必须检查 |
| --- | --- | --- |
| G01 | 普通中文/英文、混合页尺寸 | 页数、文本、字形、顺序、可复制性 |
| G02 | 0/90/180/270°、非零 Media/CropBox、UserUnit | 视觉位置、尺寸、叠加/裁剪坐标 |
| G03 | 奇数/偶数多输入、单份/末份奇数 | 双面补白位置和尺寸 |
| S01 | 多层书签、命名目的地、跨页链接 | 重排/提取后的目的页，排除页的处理 |
| S02 | 同名表单字段、Parent/Kids、Widget | 字段值、层级、外观；不得只验截图 |
| S03 | 附件、XMP、自定义 Info、页面标签、OCG | 按声明政策保留/变换/拒绝，不能静默丢失 |
| S04 | 结构树、共享资源、Type3 字体/嵌套 Form | 可见内容与语义边界、共享引用安全 |
| R01 | Docsy 防复制新版/旧版备份 | 可恢复性；旧版重编号限制保持 |
| P01 | 签章注释、AP/缺 AP/共享 AP/隐藏状态 | 打印合并外观；不能误报签名有效性 |
| P02 | 加密、密码错误、只读/签名限制 | 预检和明确错误；禁止绕开政策 |
| O01 | 原图/JPEG/Flate/蒙版/CMYK/JPX/JBIG2/条带图 | 跳过策略、体积、失真、文字可读性 |
| L01 | 300/1,000/2,000 页、100 MiB 以上 | 峰值 RSS、耗时、输出大小、取消延迟 |
| F01 | 磁盘满/目标已存在/并发同名/替换失败 | 不覆盖、不损坏、清理、不误重试 |
| F02 | 损坏 xref、对象流/递归边界、异常图像 | 有界失败/诊断，不崩溃、不误报完整 |
| X01 | macOS、Windows x64/x86 按现有支持范围 | 干净环境构建、实际文件 IO、打包后运行 |

每个样例记录输入 SHA-256、引擎提交/版本、配置、实际命令、退出码、输出哈希、页数/几何、警告、结构结果和渲染对照。真实卷宗留在本地私有路径，仓库只放可公开的合成样例。

渲染至少使用独立读者，覆盖目标页并抽查全部特殊页面；准备切默认前再做 Acrobat/WPS 等实际读者验收。像素差异先解释字体、抗锯齿、颜色管理和尺寸差异，不机械把任意单阈值当成通过。签章、印章、小字和边缘裁剪需单独查看。

大文件阈值以上，在没有内存数据前继续使用现有分段/拒绝策略。性能报告比较相同任务语义、冷/热启动与峰值内存，不能以单次小样本耗时宣称整体更快。

## 9. 检查与交付

相关代码变更后运行适当测试；现有全量命令为：

~~~sh
npm test
npm run lint
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
git diff --check
~~~

这些命令通过不能代替矩阵中的真实文件、原生 UI、Windows 和大文件验收。测试忽略项要列明；缺失 fixture 自动 return 的测试不得算真实引擎通过。

Gemini 每阶段应交付：

1. 变更文件和行为差异，解释为何需要。
2. 上游固定提交、依赖图/patch 变化和许可证记录。
3. 自动测试原始结果，包含失败及忽略数量。
4. 样例清单、输入/输出哈希、结构结果、渲染图和性能数据。
5. 尚未覆盖的矩阵项和明确限制。
6. 保持旧后端默认，说明启用候选及回退的方法。

不要把所有复选框批量勾上，不要以“健康/100%/完整保真/零残留”代替证据。不自动发布、推送或删除既有依赖。
