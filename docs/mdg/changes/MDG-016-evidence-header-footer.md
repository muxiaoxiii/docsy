# MDG-016: 证据处理模块 — 页眉页脚系统全面优化

## 状态：🔴 调研阶段
## 优先级：P0（用户反馈的 bug + 功能缺陷）

---

## 一、已确认 Bug

### Bug 1：页眉来源「固定文本」渲染错误
- **现象**：页眉来源选「固定文本」，输入 `证据[#]`，渲染出来的是证据列表名称（如「证据1」），但文件列表中显示的仍是文件名
- **期望**：文件列表中的页眉、预览渲染的页眉、最终添加的页眉三者必须一致
- **根因**：待查（固定文本的 `[#]` 替换逻辑可能与证据列表名称逻辑混用）

### Bug 2：页眉来源「按证据列表名称」显示错误
- **现象**：选「按证据列表名称」，本应生成「证据1」「证据2」这样的序列，实际使用了文件名
- **期望**：「按证据列表名称」 = 严格的「证据 + 序号」格式
- **根因**：待查

### Bug 3：序列始终从 1 开始
- **现象**：所有序列编号都从 1 开始，无法设置起点
- **期望**：支持自定义起点（如从 6 开始、从 0 开始）

## 二、功能需求

### 需求 1：删除「不添加页眉」选项
- **原因**：已有独立的页眉开关（enabled toggle），「不添加页眉」选项冗余

### 需求 2：序列参数扩展
- **当前**：`[#]` 只能生成 1, 2, 3, ...
- **提案**：
  - `[#]` → 默认从 1 开始，步长 1
  - `[#，6]` → 从 6 开始
  - `[#，0]` → 从 0 开始
  - `[#，6，2]` → 从 6 开始，步长 2（6, 8, 10, ...）
- **与模板模块对齐**：模板模块有序号格式选项（序号、序号01、序号001、中文序号），页眉页脚也应支持

### 需求 3：序列格式选项（与模板模块对齐）
- 序号：1, 2, 3, ...
- 序号01：01, 02, 03, ...
- 序号001：001, 002, 003, ...
- 中文序号：一、二、三、 ...
- 自定义格式：`[#，起点，步长]`

### 需求 4：「分段」功能评估
- **当前设计**：两个输入框，理解为某页码的起点和终点
- **问题**：页眉页脚按文件设置，分段似乎没有意义
- **需要评估**：分段功能是否应该删除或重新设计

### 需求 5：奇偶页支持
- **用户发现**：Acrobat 等 PDF 编辑器有奇偶页不同的页眉页脚功能
- **需要调研**：Acrobat、PDF Expert、WPS 等编辑器的奇偶页设计

### 需求 6：大文件页眉页脚检测优化
- **用户反馈**：证据页数过多时（300+ 页），初始检测耗时过长
- **提案**：超过阈值（300/500/1000 页，待定）时弹出提示：
  - 「页数过多，是否需要检测现有页眉页脚？」
  - 用户选「否」→ 跳过检测，直接进入添加流程
  - 用户选「是」→ 正常检测（可能较慢）
- **意义**：大多数场景用户只需要添加新页眉，不需要删除旧页眉

### 需求 7：合并完成后醒目提示
- **问题**：合并完成后只有 `ElMessage.success`（3 秒消失的 toast），用户可能没注意到
- **方案**：用 `ElMessageBox.alert` 或 `ElNotification` 显示醒目成功弹窗，包含：
  - 处理结果摘要（成功/失败/警告数量）
  - 输出路径
  - 「打开文件」「打开目录」快捷按钮

### Bug 4：删除页眉页脚失败但继续处理
- **现象**：用户标记删除现有页眉页脚，但系统找不到可安全删除的内容，只加了 warning 继续处理。最终新页眉叠加在旧页眉上
- **期望**：处理前预检，如果删除请求无法满足，弹窗告知用户「无法删除现有页眉页脚，是否继续？」
- **根因**：`standard_artifact_processing_warnings` 只在处理后生成警告，没有阻止流程
- **方案**：
  1. 处理前预检：对每个文件检测是否存在可删除的 artifact/plain text
  2. 如果有删除请求但无法删除，弹窗确认
  3. 用户可以选择「跳过删除，只添加」或「取消」
