# 视频抽帧、智能筛选与统一工作区重构方案

状态：最终实施基线
日期：2026-08-25

## 1. 目标

本次重构不是在现有缩略图列表上追加按钮，而是建立一条完整工作流：

1. 从视频抽帧，或直接载入任意图片目录。
2. 使用多个轻量视觉信号综合判断图片关系。
3. 将系统建议、判断依据和风险展示给用户。
4. 用户通过选图工作台确认保留、排除、顺序与分组。
5. 自动保存设置和筛选会话，再次打开相同或相近目录时恢复。
6. 将最终保留图片及顺序直接交给图片排版。
7. 不修改、不删除原始图片，所有自动判断都可撤销。

## 2. 产品边界

智能引擎不假设图片来自微信聊天，不假设抽帧频率固定，也不假设相邻图片一定连续。它先判断图片关系，再决定是否提出筛选建议。

关系类型：

- `duplicate`：近似重复。
- `continuous_vertical`：纵向连续位移。
- `continuous_horizontal`：横向连续位移。
- `changed`：主体相同但存在重要局部变化。
- `scene_cut`：场景或关键画面切换。
- `uncertain`：无法可靠判断。

只有连续位移关系才使用首尾重叠目标。默认目标为5%-10%，其他关系不得强制套用重叠规则。

## 3. 多信号智能引擎

### 3.1 默认纯 Rust 引擎

默认引擎只依赖现有图片解码能力和小型 Rust 算法，保证安装体积、启动速度和离线使用。

每张图片生成：

- 文件内容哈希，用于身份确认，并按路径、大小和修改时间缓存。
- 差异哈希或感知哈希，用于近似重复初筛。
- 低分辨率亮度图。
- 分块颜色和亮度签名。
- 边缘密度。
- 拉普拉斯清晰度分数。
- 图片尺寸、文件大小和修改时间。

相邻候选图综合计算：

- 全局颜色相似度。
- 亮度像素相似度。
- 感知哈希相似度。
- 变化色块比例。
- 最佳纵向位移、横向位移和有效重叠率。
- 匹配置信度。
- 两张图片的相对清晰度。

决策规则采用分层门控，而不是单一加权分数：

1. 高置信度近似重复才建议排除。
2. 局部变化超过阈值时，即使整体相似也保留。
3. 位移匹配达到阈值后才判定连续关系。
4. 连续关系的重叠高于目标时，可建议跳过中间图。
5. 重叠低于目标时保留并标记连续性风险。
6. 场景切换、低置信度和无法判断默认保留。
7. 若后图明显更清晰，可以建议保留后图并排除前图。

每次分析结果都会保存原因、指标、算法版本和被比较图片，方便解释与恢复；重新进入未变化目录时优先恢复结果，不重复消耗用户精力。

### 3.2 FFmpeg 辅助（候选增强，未进入本轮决策）

视频来源后续可使用 FFmpeg 的相似帧、场景变化信息进行第一层候选筛查，但目录图片和人工截图必须可以完全脱离 FFmpeg 运行。本轮智能决策完全由纯 Rust 图片引擎完成；未来即使接入 FFmpeg，其结果也只能作为一个信号，不能直接决定排除。

### 3.3 内嵌 OpenCV 二级增强

基础包内嵌 opencv-mobile 4.13.0 的精简静态库，用户无需下载、安装或配置 OpenCV。引擎分为两级：

- `RustVisionBackend`：默认、始终可用。
- `OpenCvVisionBackend`：对轻量引擎的低置信度结果进行二次复核。

当前 OpenCV 增强使用梯度边缘图和相位相关，输出亚像素位移及位移响应强度，重点纠正轻量像素位移搜索难以确定的连续关系。后续增强项限于：

- ORB特征点与描述子匹配。
- 相位相关或模板匹配校正位移。
- 光流辅助连续方向判断。
- 对旋转、缩放和复杂页面滚动的二次确认。

不引入DNN、OCR、人脸、视频编解码、GUI、Stitching等模块。构建仅静态链接 `core`、`imgproc` 和 `features2d`；图片解码继续由 Rust `image` 完成。

OpenCV 仅复核 `uncertain`、低置信度 `changed`、临界场景切换和置信度不足的连续关系，明确重复和明确场景切换不重复执行增强复核。C++异常被隔离在窄接口内，失败时单对图片回退到 Rust 结果，不影响整个任务。算法结果记录 `enhanced_by` 和位移响应强度供用户查看。

### 3.4 有限邻域与人工反馈

- 算法保留锚点与当前图片最多相隔2张；超过时强制改用相邻图片并安全保留当前图，禁止远距离误判。
- 用户确认保留的图片立即成为后续比较锚点。
- 用户排除的图片立即退出后续锚点候选。
- 人工操作后约220毫秒防抖重算受影响序列；图片特征按路径、大小和修改时间缓存，不重复解码。
- 人工决定和算法建议分开保存，动态重算不得覆盖人工决定。

## 4. 统一工作区持久化

### 4.1 一致的保存规则

所有模块统一使用工作区持久化服务，不再各自散落使用局部变量、`localStorage`和单独JSON。

数据分为：

- 全局偏好：预览密度、最近使用参数、默认输出格式等。
- 模块偏好：PDF工具、证据PDF、模板、格式转换、图片排版、视频抽帧各自的长期设置。
- 工作会话：文件列表、顺序、人工选择、当前任务参数和恢复信息。
- 算法缓存：内容哈希、视觉签名、清晰度和图片尺寸。
- 临时状态：进度、错误、悬停项，不长期保存。

写入采用SQLite事务和约500毫秒防抖。页面切换及应用关闭前刷新待保存修改。

### 4.2 媒体目录身份与恢复

目录恢复使用多层匹配：

1. 规范路径、文件名、大小、修改时间的快速匹配。
2. 内容哈希确认同一文件，允许改名或移动。
3. 感知哈希仅用于提示可能对应项，不自动继承排除决定。

重新载入目录时返回：

- 完全匹配数量。
- 改名或移动但内容相同数量。
- 新增数量。
- 缺失数量。
- 路径相同但内容变化数量。

完全或部分匹配时提示用户恢复、重新开始或查看变化。新增和变化项进入待确认，人工决定不得被新算法覆盖。

### 4.3 数据库

使用独立 `workspace_state.sqlite3`，避免把媒体数据耦合到模板历史数据库。

主要表：

- `workspace_preferences`
- `workspace_sessions`
- `media_session_items`
- `media_file_cache`

系统建议和人工决定必须分列保存：`engine_decision` 与 `user_decision`。人工决定优先。

## 5. 选图工作台

现有通用方形缩略图网格不再作为抽帧结果的主要界面。新工作台在当前Docsy视觉体系内实现。

### 5.1 页面结构

- 顶部摘要：总数、保留、建议排除、待确认、连续性风险。
- 工具栏：筛选视图、缩略图大小、运行分析、接受建议、撤销、发送图片排版。
- 图片墙：按原始比例显示，支持多选、拖动、保留、排除和恢复。
- 检查区：当前图与比较图并排显示，可切换单图、叠加和差异视图。
- 决策说明：关系类型、相似度、重叠率、清晰度、变化区域比例、置信度和文字原因。

### 5.2 状态表达

- 保留：使用现有深绿色强调。
- 系统建议排除：低对比警示底色，不直接消失。
- 用户排除：清晰的排除状态，可恢复。
- 待确认：中性提示。
- 连续性风险：警告状态并显示风险原因。

缩略图不堆叠全部指标，只显示状态和一条主要原因。完整指标进入检查区。

### 5.3 操作原则

- 左上角保留拖动手柄，右上角为排除或恢复。
- Delete排除，Command/Ctrl+Z撤销，方向键切换。
- 默认只从结果中排除，不删除磁盘文件。
- 接受建议只应用高置信度建议。
- 发送图片排版只发送最终保留图片和当前顺序。

## 6. 图片排版衔接

通过统一工作区传递显式图片路径、顺序和来源会话ID。图片排版不得重新扫描整个目录把已排除图片带回。返回选图工作台时筛选状态保持不变。

## 7. 交付与验证

必须覆盖：

- 纯重复、轻微压缩差异、局部变化、关键帧切换。
- 纵向和横向连续移动。
- 高重叠、目标重叠、可能缺口。
- 模糊前帧与清晰后帧替换。
- 不规则文件名和不规则抽帧时间。
- 目录未变化、部分新增、缺失、改名、内容替换。
- 页面切换、应用重启、异常退出后的恢复。
- 数百和数千张图片下的内存与交互性能。
- 图片排版接收的数量和顺序与选图结果一致。

完成标准不是算法自动排除尽可能多，而是：高置信度结果可靠、低置信度结果透明、用户决定可恢复、完整工作流不丢状态。

## 8. 本轮实现状态

已完成：

- 纯 Rust 多信号关系判断和可解释指标。
- 内嵌 OpenCV 梯度相位相关二级复核，以及复核来源和位移响应展示。
- 最多跨2张的有限邻域、人工锚点和基于用户纠正的动态阈值更新。
- 自动抽帧后分析，以及直接打开已有图片目录。
- 保留、排除、恢复、撤销、拖动排序、筛选视图和大图对比。
- 结果出现后自动进入宽屏审核模式，可随时显示抽帧设置。
- SQLite 工作区偏好、媒体会话、文件身份缓存和部分目录恢复。
- 页面切换期间保留当前工作台，应用重启后可按目录恢复已保存结果。
- 最终保留图片按当前顺序直接发送图片排版，排版模块只处理显式图片列表。
- PDF工具、证据PDF、Markdown转换、模板、图片排版和视频抽帧使用同一偏好保存机制。

后续可继续增强：

- OpenCV ORB、光流和尺度变化二次确认（梯度相位相关已内嵌实现）。
- FFmpeg `mpdecimate`、`scdet` 候选筛查。

上线前仍需使用真实证据截图样本建立误判集，分别统计重复、关键变化、纵向连续、横向连续和低纹理画面的准确率。算法版本升级不得覆盖既有人工决定。

## 9. 参考方案与借鉴边界

- [Adobe Bridge Review Mode](https://helpx.adobe.com/bridge/desktop/organize-and-find-files/organize-files-and-folders/preview-images-and-edit-capture-time.html)：借鉴快速浏览、排除和保留的审核流程，不照搬其素材管理结构。
- [digiKam Light Table](https://docs.digikam.org/en/light_table/lighttable_advanced.html)：借鉴前后图并排、同步观察和差异判断。
- [Czkawka Core](https://github.com/qarmin/czkawka/blob/master/instructions/Instruction_Core.md)：借鉴内容哈希缓存和重复扫描的复用思路。
- [FFmpeg Filters](https://ffmpeg.org/ffmpeg-filters.html)：`mpdecimate`、`scdet`、`thumbnail` 可作为视频候选信号，不适用于任意图片目录的最终决策。
- [OpenCV BUILD_LIST](https://github.com/opencv/opencv/blob/4.x/CMakeLists.txt)：可裁剪模块，但基础包不能直接假定桌面端体积可接受。
- [opencv-mobile](https://github.com/nihui/opencv-mobile)：证明移动端存在精简构建路径；其公布体积不能代替 Docsy 对 macOS 和 Windows 实际安装包的测量。
